# Happ VLESS subscription

Автоматически обновляемая подписка VLESS Reality для Happ. Генератор напрямую
использует несколько независимых публичных источников, проверяет соединение через
Xray и публикует небольшой разнообразный набор серверов.

## Как обновляется список

Workflow запускается каждые 2 часа и:

1. Загружает конфигурации напрямую из ConnLiberty, `vpn-free-russia`,
   `ProxyCollector`, `barry-far` и `0xRadikal`. Отказ одного источника не
   останавливает остальные; сетевые сбои автоматически повторяются.
2. Оставляет VLESS Reality с транспортом TCP/RAW и удаляет точные дубликаты.
   Если лента содержит больше 300 подходящих узлов, равномерная выборка
   ротируется каждые два часа по всей ленте, а не застревает на первых строках.
3. Делает быстрый TCP-предфильтр, параллельно определяет географию и кэширует её
   на сутки. В полный тест попадает объединение 60 ближайших к Москве и 40 самых
   отзывчивых для GitHub-раннера, поэтому расположение Actions не вытесняет
   близкие к пользователю узлы.
4. Для пула кандидатов запускает Xray и запрашивает HTTPS-страницу через настоящий
   SOCKS-туннель. У 30 лучших дополнительно измеряет загрузку 256 КБ и проверяет
   настоящий UDP round-trip через SOCKS5 и DNS, доступ к Telegram API и успешное
   открытие Gemini. Открытого порта недостаточно.
5. Исключает российские и неопределённые выходные IP и выбирает до 20 узлов с
   разными адресами и `/24`-подсетями. Сначала выбираются разные UUID, ASN и страны;
   повтор UUID допускается только резервным проходом для другого адреса и подсети.
   При наличии хотя бы 10 качественных узлов список обновляется, не дожидаясь ровно 20.
6. Ранжирует по расстоянию от Москвы, пропускной способности, стабильности за
   последние 12 запусков, разбросу задержки и редкости адреса в источниках.
   Расстояние указывается в имени узла. Без Provider ID автоматическая сортировка
Happ может быть недоступна, поэтому точный локальный пинг запускается кнопкой
спидометра в приложении.
7. Записывает `generation_status.json` с временем последней успешной сборки и
   количеством прошедших узлов. Если качественных серверов меньше безопасного
   минимума, старый список сохраняется, но GitHub Actions показывает предупреждение
   и состояние `degraded` вместо тихого успеха.

Публичные бесплатные серверы не дают достоверной статистики одновременных
пользователей. Генератор снижает вероятность перегруженного общего пула с помощью
реальной проверки, сетевого разнообразия и предпочтения адресов, встречающихся в
меньшем числе источников.

## Настройка

Список источников можно заменить через многострочную переменную `VLESS_SOURCES`:

```text
source-name=https://example.com/subscription
backup=https://example.net/vless.txt
```

Основные переменные:

- `VLESS_LIMIT` — число опубликованных узлов, по умолчанию `20`;
- `VLESS_MIN_SERVERS` — безопасный минимум для обновления, по умолчанию `10`;
- `MAX_CANDIDATES_PER_SOURCE` — верхняя граница кандидатов от одной ленты,
  по умолчанию `300`;
- `SOURCE_ROTATION_SECONDS` — период смены выборки больших лент, по умолчанию
  `7200` секунд;
- `REALITY_TEST_LIMIT` — сколько кандидатов проверять через Xray, по умолчанию `100`;
- `REALITY_TEST_WORKERS` — число параллельных проверок, по умолчанию `4`;
- `ADVANCED_TEST_WORKERS` — параллельные тесты скорости и UDP, по умолчанию `6`;
- `THROUGHPUT_BYTES` — размер контрольной загрузки, по умолчанию `262144` байта;
- `MIN_THROUGHPUT_MBPS` — минимальная скорость финального узла, по умолчанию
  `0.5` Мбит/с;
- `SERVICE_TEST_TIMEOUT` — тайм-аут отдельных проверок Telegram и Gemini,
  по умолчанию `7` секунд;
- `STALE_WARNING_HOURS` — возраст последнего успеха, после которого выводится
  предупреждение, по умолчанию `6` часов;
- `REALITY_TEST_TIMEOUT` — тайм-аут одной проверки, по умолчанию `8` секунд;
- `MAX_REALITY_LATENCY_MS` — максимальное время реального HTTPS-теста, по умолчанию
  `3500` мс;
- `XRAY_BIN` — путь к исполняемому файлу Xray.

Ручной запуск обновления: Actions → Update VLESS subscription → Run workflow.

По умолчанию измерения выполняются из GitHub-hosted `ubuntu-latest`, поэтому
расстояние до Москвы остаётся географической поправкой, а не настоящим московским
RTT. Для собственного регионального runner можно задать repository variable
`VPN_RUNNER` с его label. Для публичного репозитория постоянный self-hosted runner
следует изолировать и не разрешать запуск непроверенного кода из pull request.

## Маршрутизация в Happ

Подписка импортирует один профиль `Dmitry RU Direct` и при следующих обновлениях
перезаписывает его, а не создаёт новый профиль. Российский трафик определяется в
два этапа: по доменам (`.ru`, `.рф`, `russia-inside`, `category-ru`) и по IP
(`direct`, `russia-inside`). Остальной трафик идёт через VPN. Для Telegram также
заданы доменные правила и его IPv4/IPv6-подсети, чтобы приложение не отправляло
IP-подключения Telegram напрямую.
Gemini и связанные домены авторизации/API Google всегда направляются через VPN.
Версия профиля меняется раз в сутки: при очередном автообновлении Happ повторно
импортирует правила и освежает кэш GeoSite/GeoIP без загрузки файлов каждые 2 часа.
Подсети Telegram загружаются заново при каждой сборке, валидируются и при сбое
источника безопасно откатываются к проверенному набору из `routing_profile.json`.

В Happ маршрутизация изолирована для каждой подписки. После импорта или изменения
профиля нужно открыть «Маршрутизация» у подписки `Fast VPN`, включить общий
переключатель и переподключить VPN. Переключение между серверами внутри `Fast VPN`
должно сохранять этот режим; при переходе на сервер из другой подписки используется
её отдельная настройка маршрутизации.

Старый профиль `Fast VPN TEST RU+Gemini`, если он уже был импортирован в Happ,
нужно удалить в приложении один раз вручную. Happ не предоставляет deeplink для
удаления отдельного профиля; подписка больше этот тестовый профиль не импортирует.
